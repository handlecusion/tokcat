# AGENTS.md

Project-specific instructions for agents working on Tokcat.

## What this is

Tokcat is a native macOS menubar dashboard for AI coding token usage.
Since 0.2.0 the app is **Swift + SwiftUI** (`native/`); the Tauri 2 shell (`src-tauri/` + `src/`) is retained only as the 0.1.x bridge and as the parity reference for the ported collector. Distribution is via GitHub Releases (universal DMG + Sparkle auto-updater) and a Homebrew tap.

## Layout

- `native/Tokcat` — app target (`TokcatApp.swift`, `Info.plist`, icon). The Xcode project is generated by XcodeGen from `native/project.yml` and is **not** committed.
- `native/LocalPackage` — SwiftPM package, layered one-way `UserInterface → Model → DataSource`:
  - `Collector` — the usage-data layer ported from `src-tauri`: parsers, pricing, tailer, quota providers. Imported only by Model's composition root and the parity CLI.
  - `Model` — stores, menubar/status-item controller, tray animation, Sparkle `UpdateService`, Tauri-era settings migration.
  - `UserInterface` — SwiftUI views only, no logic.
  - `tokcat-dump` — parity CLI (`graph`, `tail-sim`, `tail-live`).
- `src-tauri/`, `src/` — legacy Tauri/React app. Do not add features here; it exists for `scripts/parity-check.sh` and the 0.1.x bridge release.

Build settings live in `native/project.yml`, not in the generated `.xcodeproj`.

```sh
cd native && xcodegen generate && open Tokcat.xcodeproj
cd native/LocalPackage && swift build && swift test
scripts/parity-check.sh --snapshot     # Swift vs Rust collector diff
```

## Repos involved in a release

There are **two** repositories. A release touches both — never forget the tap.

1. **`~/Code/tokcat`** (this repo, `handlecusion/tokcat`) — app source, GitHub Releases, updater manifests.
2. **`~/Code/homebrew-tokcat`** (`handlecusion/homebrew-tokcat`) — Homebrew tap with `Casks/tokcat.rb`. Brew users install from here.

## Release procedure

Releases are driven by **GitHub Actions**: push a `v<version>` tag and `.github/workflows/release-native.yml` builds the universal app, publishes the GitHub Release, and rewrites the cask in the tap. `scripts/release-native.sh` is the manual fallback for the same flow on a local Mac. (`.github/workflows/release.yml` only fires on `v0.1.*` tags — the retired Tauri bridge.)

### Required GitHub Secrets (one-time setup)

In `https://github.com/handlecusion/tokcat/settings/secrets/actions`:

- `SPARKLE_PRIVATE_KEY` — the Sparkle EdDSA private key (public half is `SUPublicEDKey` in `native/project.yml`; private half also lives in the login keychain, account `tokcat`)
- `TAURI_SIGNING_PRIVATE_KEY` — full contents of `~/.tauri/tokcat.key`, the minisign key every 0.1.x client verifies against
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — optional, only if that key is password-protected
- `HOMEBREW_TAP_TOKEN` — PAT with write access to `handlecusion/homebrew-tokcat` (classic `repo` scope, or fine-grained `Contents: read/write` on that repo)

### 1. Bump both versions in `native/project.yml`

- `MARKETING_VERSION` — must equal the tag (`v<MARKETING_VERSION>`); the workflow fails otherwise.
  **Always bump the patch component** — `0.3.0` → `0.3.1`, never a minor bump, not even for a new feature such as another supported client.
- `CURRENT_PROJECT_VERSION` — must be **greater** than the latest release's `sparkle:version`. Sparkle compares this, not the marketing version: forgetting it ships an appcast every Sparkle client silently ignores while the legacy `latest.json` channel still updates, splitting the fleet.

### 2. Commit

Group changes into focused commits. The version bump goes in its own commit named exactly `Release Tokcat <version>` (matches existing history).

### 3. Push `main`, then the tag

```sh
git push origin main
git tag -a v<VERSION> -m "<release notes>"   # annotated — message becomes the GH Release body,
git push origin v<VERSION>                   # the appcast description, and latest.json notes
```

Unannotated tags work too; the workflow falls back to `"Tokcat <VERSION>"`.

The workflow then:
- Verifies the tag against `MARKETING_VERSION` and the build number against the previous appcast
- Builds `ARCHS="arm64 x86_64"` ad-hoc-signed on `macos-15`, and asserts the binary is really universal
- Tars the bundle with `COPYFILE_DISABLE=1` and asserts no AppleDouble members and intact `Sparkle.framework/Versions` symlinks
- Signs the tarball twice: minisign (legacy channel) and Sparkle EdDSA
- Generates `latest.json` + `appcast.xml`
- **Enforces all five assets**, then creates the release and rewrites `Casks/tokcat.rb` in the tap

### 4. Verify

```sh
gh run watch
gh release view v<VERSION>   # five assets + the .dmg.sha256
brew update && brew info --cask handlecusion/tokcat/tokcat
```

### Manual fallback: `scripts/release-native.sh`

Same artifacts and same gates, run locally. Requires `xcodegen`, `jq`, `npx`, `python3`, `gh`, and both keys:

- minisign: `~/.tauri/tokcat.key` (or `TAURI_SIGNING_PRIVATE_KEY_PATH`)
- Sparkle: `~/.tauri/tokcat-sparkle-ed25519.key` (or `SPARKLE_PRIVATE_KEY_PATH`)

The script requires the tag to already exist. It publishes the release but leaves the tap to you:

```sh
DMG_URL="https://github.com/handlecusion/tokcat/releases/download/v<VERSION>/Tokcat_<VERSION>_universal.dmg"
curl -sL "$DMG_URL" | shasum -a 256
# Edit ~/Code/homebrew-tokcat/Casks/tokcat.rb — version + sha256 (single universal artifact)
cd ~/Code/homebrew-tokcat && git commit -am "tokcat <VERSION>" && git push origin main
```

## Invariants — do not break these

- **Five assets, every release**: `Tokcat_<v>_universal.dmg`, `Tokcat_<v>_universal.app.tar.gz`, its `.sig`, `latest.json`, `appcast.xml`. Both update channels are served forever — Sparkle for the native app, minisign/`latest.json` so any surviving 0.1.x install auto-updates straight into the Swift app.
- **Never delete a release or mark one as prerelease.** `releases/latest/download/*` would then resolve to a release without manifests and strand every updater.
- **The executable name stays lowercase `tokcat`** (`EXECUTABLE_NAME` / `CFBundleExecutable`) even though the bundle is `Tokcat.app` — the legacy Tauri updater relaunches `Contents/MacOS/tokcat` by path.
- **`COPYFILE_DISABLE=1` on the updater tarball.** macOS `tar` otherwise embeds AppleDouble (`._*`) members that macOS `tar -tzf` hides but the Rust tar crate in `tauri-plugin-updater` chokes on — verified by the local 0.1.42→0.2.0 e2e test.
- **macOS 13 is the floor** (`deploymentTarget`, `LSMinimumSystemVersion`, cask `depends_on macos: ">= :ventura"`). macOS 11/12 users stay on `v0.1.42`.

## Claude harness (issue → cloud session → PR → gated merge)

Owner-only automation, documented in `.claude/harness/README.md`:

- Owner adds the `claude` label to an issue → `.github/workflows/claude-dispatch.yml`
  verifies the actor is the repository owner, builds a payload (issue, discussion,
  `AGENTS.md`, `docs/llms-full.txt`, referenced specs), fires the Claude Code
  **routine** over its `/fire` API, and comments the session link on the issue.
  The session shows up in the Claude desktop/mobile apps.
- The session follows `.claude/harness/ROUTINE_PROMPT.md`: asks on the issue when
  requirements are missing (`claude:needs-info`), otherwise works on
  `claude/issue-<N>`, opens a PR with a verification section, and posts a
  self-review note. Reply with `@claude` to continue (`claude-followup.yml`).
- Merge gate (`claude-merge-gate.yml`): owner approval (review **Approve**, or the
  `approved` label for Claude's own PRs) enables auto-merge; the `protect-main`
  ruleset requires the three CI jobs, so nothing lands before CI is green.
- Every opened PR also gets an automatic COMMENT review from a second routine
  (`.claude/harness/REVIEW_PROMPT.md`) via a GitHub trigger — it never approves.
- Secrets: `CLAUDE_ROUTINE_FIRE_URL`, `CLAUDE_ROUTINE_FIRE_TOKEN` (per-routine
  token; it can only fire that routine). No Claude credentials on runners.
- Sessions write to GitHub as the owner *via the Claude GitHub App*
  (`performed_via_github_app`); the workflows use that to tell a human apart
  from a session, so never post `@claude` or the `approved` label from a session.
- If you rename a CI job, update the ruleset's required checks too.

## Repo conventions

- **Commit style**: short imperative subject (~70 chars), optional body explaining the *why*. See recent history.
- **Lockfiles**: `package-lock.json` is committed; `pnpm-lock.yaml` is ignored and should not be committed.
- **CI** (`.github/workflows/ci.yml`) runs on every PR: Swift build + test + xcodegen app build (asserting the lowercase executable), plus the legacy frontend typecheck and `cargo check`/`cargo test` for the bridge.
- **Parser changes go to Swift.** New client formats belong in `native/LocalPackage/Sources/Collector/Parsers`. Touch the Rust reader only if you also need the parity harness to keep passing.
- **Dev server port** `4061` only matters for the legacy web frontend (`node server.js`). If you see `EADDRINUSE`: `lsof -nP -iTCP:4061 -sTCP:LISTEN -t | xargs -r kill`.

## Things that have bitten us before

- **Forgetting the tap**: a manual `release-native.sh` run does **not** update Homebrew users. The tap repo is separate.
- **Forgetting `CURRENT_PROJECT_VERSION`**: the release succeeds, Sparkle clients silently never see it.
- **Tag conflicts**: if a release must be redone, delete the tag locally and remotely (`git tag -d v0.2.x && git push origin :refs/tags/v0.2.x`) — but bumping to the next patch is usually safer than overwriting a published release.
- **Minisign signing flags**: the Tauri CLI reads `TAURI_SIGNING_PRIVATE_KEY(_PASSWORD)` from the env and aborts if `-f`/`-p` are also passed. Env vars only (v0.2.0's first release run failed on this).
- **`Casks/tokscale.rb` in the app repo**: a stale leftover from the `tokscale-3d` rename, deleted. The cask lives in the tap repo; do not recreate it here.
